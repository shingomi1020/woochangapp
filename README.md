# 업무관리 앱 기획안

## 1. 제품 방향

이 앱은 **투두리스트 + 캘린더 기반 업무관리 앱**으로 시작하고, 이후 아래 기능으로 확장하는 것을 목표로 합니다.

- 견적서
- 거래명세서
- 자동견적서
- 인사관리
- 월급 관리

핵심은 기능을 하나씩 붙이는 것이 아니라, 처음부터 **업무 / 일정 / 거래 / 인사**가 연결되는 구조로 설계하는 것입니다.

## 2. 추천 MVP

처음에는 기능을 넓게 만들기보다 아래 4가지를 제대로 만드는 것이 좋습니다.

- 할 일 등록, 수정, 완료 처리
- 캘린더 일정 등록, 수정, 반복 설정
- 할 일과 일정 연결
- 오늘 할 일 / 이번 주 일정 대시보드

이 MVP만 잘 만들어도 실제 업무관리 도구로 바로 사용할 수 있고, 이후 기능 확장이 쉬워집니다.

## 3. 핵심 개념

처음부터 아래 개념을 분리해서 설계하는 것을 추천합니다.

### Task

- 해야 할 일
- 우선순위
- 마감일
- 상태
- 담당자

### Event

- 캘린더 일정
- 시작일시 / 종료일시
- 반복 여부
- 관련 업무 연결

### Client

- 거래처 / 고객
- 견적서, 거래명세서와 연결

### Document

- 견적서
- 거래명세서
- 자동 생성 문서

### Employee

- 직원 정보
- 급여 정보
- 인사 기록

## 4. 확장 가능한 구조

처음부터 아래처럼 모듈 단위로 나누면 나중에 기능이 커져도 관리하기 쉽습니다.

- `dashboard`: 오늘 할 일, 일정, 알림
- `tasks`: 투두리스트 관리
- `calendar`: 일정 관리
- `clients`: 거래처 관리
- `documents`: 견적서, 거래명세서
- `hr`: 직원, 급여, 인사 관리
- `settings`: 권한, 회사 정보, 문서 설정

## 5. 권장 데이터 흐름

아래 흐름이 만들어지면 앱의 확장성이 좋아집니다.

1. 업무(Task)를 만든다.
2. 필요하면 일정(Event)과 연결한다.
3. 특정 거래처(Client)와 연결한다.
4. 업무가 진행되면 견적서/명세서(Document)를 생성한다.
5. 담당 직원(Employee)와 연결해 인사/급여 데이터로 확장한다.

즉, 모든 기능이 따로 노는 것이 아니라 하나의 업무 흐름으로 연결되어야 합니다.

## 8. 추천 기술 방향

아직 기술스택이 정해지지 않았다면 아래 조합이 안정적입니다.

- 프론트엔드: Next.js
- 백엔드: Next.js API 또는 Supabase
- 데이터베이스: PostgreSQL
- 인증: NextAuth 또는 Supabase Auth
- 일정 UI: FullCalendar 계열 라이브러리

이유는 다음과 같습니다.

- 일정/문서/대시보드까지 웹앱으로 확장하기 좋음
- 관리자형 서비스 구조에 적합함
- PostgreSQL은 관계형 데이터가 많은 업무관리 앱에 잘 맞음

## 9. DB 설계 시 꼭 넣어야 할 것

초기부터 아래 컬럼 성격은 공통으로 넣는 것을 권장합니다.

- `id`
- `created_at`
- `updated_at`
- `deleted_at`
- `status`
- `owner_id`

그리고 대부분의 핵심 테이블은 나중에 서로 연결될 수 있어야 합니다.

- `tasks`
- `events`
- `clients`
- `documents`
- `employees`
